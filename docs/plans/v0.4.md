# v0.4 plan: learning, knowledge and connections

Goal (roadmap.md): agents know your world, and connecting things is easy. Same shared rules as `docs/plans/v0.3.md`
(tests at every layer, `make check` green, `docs/api.md` updated, secrets through `secrets.Store`, one app.db
connection, plain copy). Workstreams run in worktrees from `main`, in two waves.

## Wave 1

### G. Memory M2 and M3

Builds on M1 (`internal/memory`, `runtime/src/lib/memory.ts`, Settings → You).

- **Suggestions at the end of a conversation**, behind one system-wide switch (Settings → You, off by default): when a
  conversation has been idle 10 minutes after a reply, the app asks the agent's model (one small request, through the
  runtime) for at most 3 facts worth keeping about the person, saved as suggestions (`trust: inferred`,
  `status: suggested`) with the conversation as their source. Never for conversations started by a schedule or
  another agent. With fast judgments on (use `memory`), each candidate is judged ("is this a durable fact about the
  person, not a one-off?") and dropped below the threshold.
- **Before compaction**: when pi compacts a long conversation, the same extraction runs on what is about to be
  summarized (pi-durable's compaction hooks), so facts aren't lost to the summary.
- **Trust labels and history**: each fact shows where it came from (you said it / an agent inferred it / from outside
  text) everywhere it's listed; edits keep a history (`user_memory_history`), shown under a fact ("Changed from … on
  Oct 21").
- **`search_conversations`**: a tool that searches the agent's own conversations (never other agents'), through the
  app's message search (`internal/search`, FTS5), returning snippets with conversation titles and dates; on by
  default with memory.
- **Embeddings (optional, off)**: if a provider offers an embedding model, recall and search_conversations can rank
  by meaning; a setting picks the model. Skip if it doesn't fit the time; say so.

### H. Knowledge folders and the Document Q&A template

- An agent gets **knowledge folders** (`agent.yaml` `knowledge: {folders: [paths]}`): folders on this computer whose
  documents it can search and cite. The app indexes them: text files, Markdown, PDF, Word, Excel, PowerPoint (the
  runtime's converters, run as `node runtime.mjs --extract <file>` so Go can call them), split into passages, in an
  FTS5 index in app.db (`knowledge_*` tables), kept fresh by watching the folders (and a rescan on start).
- A **`search_knowledge`** tool (query → passages with file, page or sheet, and a link), and `read` of those files even
  outside the workspace (read-only).
- **Reranking with fast judgments** (use `knowledge`): the top 20 passages judged for relevance, best 5 returned.
- **Document Q&A** template: answers only from the knowledge folders, cites every claim, says when the documents don't
  say.
- UI: the agent's Knowledge tab (add folders with the folder dialog, index status: files, passages, last update,
  errors), and citations in replies link to open the file (`/api/open-url` with a file URL, or reveal).

### I. Skills, slash commands and a prompt library

- **Skills** (pi's format: a folder with `SKILL.md`, front matter `name`, `description`): per agent (`<agentDir>/skills/`)
  and shared (`<data>/skills/`, picked per agent). The runtime lists them in the prompt (name and description) and the
  agent reads one with `read` when it applies. UI: the agent's Skills tab (add from a folder or a zip, enable, view).
- **Prompt library**: saved prompts (title, text with `{{placeholders}}`), in `<data>/prompts/` as Markdown files.
  Settings → Prompts to add, edit, import and export.
- **Slash commands** in the composer: `/` opens a menu of prompts (and built-ins: `/new`, `/model`, `/clear`-like ones
  that make sense); choosing one fills the composer, asking for placeholders inline.

## Wave 2

### J. Artifacts / canvas

- An `artifact` tool: the agent creates or updates a named work product (Markdown document, code file, HTML page, CSV
  table) kept as an exposed conversation document (`artifacts`), with versions.
- A canvas panel beside the conversation: view (rendered Markdown, highlighted code, sandboxed HTML preview in an
  iframe with no scripts by default, table), edit by hand (saved back as a version the agent sees), copy, download,
  save to the workspace.

### K. Agent builder and Concierge templates

- **Agent builder** template: a conversation that designs a new agent with the person (purpose, instructions, tools,
  schedule, knowledge), then creates it through a `create_agent` tool (always asks for approval, showing the whole
  `agent.yaml`). Also `update_agent` for agents it made.
- **Concierge** template: the front door. It knows your agents (list_agents), hands a request to the right one
  (ask_agent, with fast-judgment routing when on), and answers simple things itself.

### L. Connections gallery

- A gallery of connections built on MCP, for people who shouldn't need to know what MCP is: each entry is a curated
  MCP server preset (name, icon, what it lets agents do, how it signs in), with "Connect" (OAuth in the browser for
  remote servers; an install step for local ones) and which agents use it.
- First set (decided):
  - **Sign in and done** (remote MCP with OAuth): Notion, GitHub, Linear, Atlassian (Jira, Confluence), Asana.
  - **Mail, calendar, files**: Microsoft 365 (Outlook mail and calendar, OneDrive) and Google (Gmail, Calendar, Drive),
    as "Advanced" until there are servers that don't need your own OAuth app.
  - **On this computer**: Apple Calendar, Reminders and Notes on macOS (Mac first, others in v0.5), the file system
    (already the workspace tools).
- Then the **calendar tool** and the **Inbox helper** and **Meeting helper** templates, on top of the connections.
