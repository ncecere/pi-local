# v0.5 plan: Windows and Linux

Implementation is in progress in isolated v0.5 worktrees after the v0.4 releases. Reference repositories remain
read-only. All implementation/review/QA agents use `openai-codex/gpt-6.1-sol`; the person alone chooses the v1.0 launch.
See [verification progress](../qa/v0.5.md) for integrated evidence and remaining gates; this plan is not a claim of
Windows/Linux desktop readiness.

## Initial support targets

- Preserve macOS arm64 and its existing data location/update behavior.
- Add Windows 11 x86_64 with WebView2.
- Add Ubuntu 24.04 x86_64 with GTK4/WebKitGTK 6.0, checking both X11 and Wayland.
- Do not imply support for every Linux distribution, musl, Windows/Linux arm64 or macOS Intel without evidence.
- Continue unsigned/ad-hoc pre-v1.0 distributions with honest install warnings. Broader signing policy or privileged
  installation needs a separate decision. Keep the existing Ed25519 update trust root and signature format.

## Source assessment

This initial assessment used v0.4 candidate `544b6da` and cached Wails `v3.0.0-beta.22` source, not native Windows/Linux
execution. Subsequent portable-kernel/fake-backed native tests are recorded in the verification document; they do not
establish native desktop, vault or confinement parity. The list below preserves the original porting inventory.

- `cmd/pi-local/main.go`: macOS chrome/tray, bundle-relative Node, `/usr/bin/open`, Unix relaunch, unconditional native
  `TrustedHumanConfirmations` capability.
- `cmd/pi-local/desktop.go`: .app detection, osascript notifications and LaunchAgent login startup.
- `internal/app/app.go`: Unix file locking, openers and environment assumptions.
- `internal/supervisor/supervisor.go`: Unix process groups/signals.
- `internal/runtimeenv/runtimeenv.go`: colon-delimited PATH, `node`, executable bits and zsh fallback.
- `internal/secrets/secrets.go`: cross-platform go-keyring underneath, but its Windows backend caps a value at
  2,560 bytes; serialized OAuth state needs an explicit tested design.
- `internal/update/update.go`: macOS-arm64 archive selection; install implementation only on Darwin.
- `runtime/src/lib/sandbox/`: Linux/Windows stubs; shell/probe paths and defaults are Darwin-oriented.
- `packaging/licenses/`: notice discovery currently assumes a Darwin production Go target.

## 1. Prove the human-control boundary

Source evidence: Wails Windows uses WebView2 WebResourceRequested interception for `http://wails.localhost`; Linux
registers the `wails` URI scheme. Wails' assetserver simulates HTTP handling in-process. These native paths are not
inherently loopback TCP servers; that is not a substitute for per-platform runtime verification.

Keep the unauthenticated headless dev server confined to synthetic testing. Before enabling trusted native decisions:

- Inventory listeners in a packaged build; try management/approval/elicitation/policy/secret routes from an agent's
  shell and unrelated local process.
- Exercise hostile Host/Origin/window headers, remote navigation, iframes, replay and dev-server configurations.
- If management becomes TCP-reachable, add a UI-only credential bootstrapped over verified native transport. Never
  expose it through unauthenticated assets, agent env/gateway keys, workspace, disk or logs. CORS/random ports alone
  do not establish human authorization.
- New-platform notifications should open the approval UI rather than directly approve until activation provenance
  is proved. Windows encoded activation payloads and Linux sender handling need explicit scrutiny.

Apple tools remain macOS-only; imported configurations must fail honestly elsewhere.

## 2. Extract host and process contracts

Introduce platform-specific implementations behind explicit capabilities for open/reveal, login startup,
notifications, restart, share ingress and availability/status. Avoid broad platform flags scattered through UI code.

Split file locking and process control by OS. Keep Unix process groups on macOS/Linux; use Windows Job Objects,
graceful stdin-watchdog shutdown and bounded forced termination for descendants. Test cancellation and orphan cleanup.

Use OS-aware PATH handling and `node.exe` discovery. Define packaged layouts rather than guessing paths. Extend the
shell environment allowlist only for required Windows variables; never restore broad parent-env inheritance.
Preserve existing agent folders, state and data locations.

## 3. Keyrings and sandboxing

- Distinguish locked/unavailable keyring from missing credentials. Linux without Secret Service must explain how to
  fix it and refuse persistent writes; no silent plaintext or memory fallback. Session-only memory is an explicit
  choice. Test with isolated fake/keyring services, never personal credentials.
- Resolve Windows large-token storage with authenticated OS-protected storage and atomic/versioned update behavior;
  test OAuth-sized blobs and interrupted writes before claiming provider parity.
- Implement Linux bubblewrap and a Windows AppContainer launcher/helper. Extend shell selection and harmless sandbox
  probes; Git Bash is a possible explicit Windows prerequisite, not a silent WSL/download substitution.
- Missing/failed confinement refuses execution. Never silently turn off a saved sandbox policy.
- Test workspace/temp writes, denied credentials/other-agent data, keyring IPC, parent-process inspection,
  symlinks/junctions, network-off, descendants/cancellation, and unavailable engines. Network-enabled confinement
  must not inadvertently expose host credential/control IPC. Scope and clean up AppContainer ACL grants narrowly.

## 4. Native desktop and send/share ingress

Wire tray, notifications, autostart, dialogs, chrome and keyboard conventions through the contracts. Without a Linux
tray host, retain an accessible window and quit path.

Normalize share/context-menu input into a bounded choose-agent-and-preview flow. Never execute or send automatically.
Cover cold launch, second-instance delivery, Unicode/spaces, hostile filenames, argument injection and cancellation.

## 5. Transactional packaging and updates

- Select exact version/OS/architecture assets; retain Ed25519 filename-plus-digest verification.
- Validate archives before installation: traversal, drive/UNC/absolute paths, ADS/reserved names, case collisions,
  duplicates, expansion bounds, links/reparse points and payload identity. Reject links by default; validate any
  necessary internal macOS bundle links explicitly.
- Windows helper must live outside the replacement tree, wait on the actual process handle, revalidate staged inputs,
  handle locked executables, journal recovery and keep rollback until successful restart.
- Linux stages on the same filesystem and uses rename. Backups must succeed first. Never replace user data with the
  app installation. Cover interruptions, disk-full, permissions, failed relaunch and schema-compatible recovery.
- Pin/checksum Node distributions for each target. Extend notice discovery to explicit GOOS/GOARCH/CGO and all shipped
  helpers. Preserve full terms and fail-closed inventories; Darwin output is not evidence for another target.

## Workstream sequencing

1. Host/process/lock contracts and human-control tests first; serialize shared wiring.
2. Then independent secrets, Linux sandbox, Windows sandbox, desktop ingress and packaging/update worktrees.
3. Integrate changes to defaults, transport, dependency manifests, Makefile and workflows deliberately, not by blind
   merge. Read fixes and run integrated gates after independent branch tests.

## Native CI and release gates

Use pinned Go/Node/pnpm. macOS needs Xcode tools; Windows needs WebView2 and explicit shell prerequisites; Linux needs
compiler/pkg-config, GTK4/WebKitGTK6, X11, bubblewrap, isolated D-Bus/keyring and display sessions. Verify package names
against the pinned runner images rather than copying GTK3-era instructions.

Each native lane must cover builds/tests, UI API SSE/uploads, model/approval cancellation, durable crash recovery,
folder portability, backup/restore, keyring failures, sandbox boundaries and management-route isolation. Validate
signatures/checksums/versions/notices of actual artifacts. Publish only after all required lanes pass. Be explicit
about browser automation versus native WebView testing and about any unsupported desktop integrations.

No telemetry, no automatic model routing, no global quick-ask hotkey, and no v1.0 publication without the person's
choice. Broader platform claims, privilege-requiring setup or changes to signing policy require further input.
