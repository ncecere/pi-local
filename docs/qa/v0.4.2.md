# v0.4.2 verification — published assets verified

[v0.4.2](https://github.com/ncecere/pi-local/releases/tag/v0.4.2) is a security-only rebuild of v0.4.1 with
Go 1.26.10. Immutable source: `8932c385f80ab3040ad59cc4dc7556a08cbb7dad`. No v0.5 foundations are included.
The test-only memory synchronization backport does not change production suggestion behavior.
See [toolchain security verification](go1.26.10-security.md) for advisory reachability and immutable legal provenance.

## Implementation and pre-release gates

- Independent security review approved the patch, all fourteen official advisory records and pinned legal inputs.
- Full check passed all Go checks, 401 runtime tests, 915 frontend tests and ten notice tests.
- Five targeted race repetitions passed; desktop/server govulncheck reported no vulnerabilities found on Darwin/arm64.
- Both built binaries identified Go 1.26.10; dependencies and frozen lockfiles were unchanged.
- Main CI [39691289651](https://github.com/ncecere/pi-local/actions/runs/39691289651) passed on the exact tag source.
- Clean-source `RELEASE=1` packaging with an initially empty Go module cache passed. Release signing credentials
  were unset locally. ZIP/DMG integrity, both checksums, strict ad-hoc signature and clean Go 1.26.10 binary
  metadata passed; output is `.cache/v042-cold-package/`. The unsigned local update ZIP was not published.

Two isolated headless/browser runs on the exact source completed the bounded pre-release smoke:

- Distinct repeated `call_1` approval occurrences survived restart/reload. B never executed before actual UI approval.
  Parsed approved/stored YAML matched across all fields and types, schedules matched, and three replays per proposal
  returned the same completed receipt without changing relevant rows or creating another child/schedule.
- An initial byte-exact YAML assertion was a harness error: disk serialization deliberately adds a comment and uses
  two-space indentation. Semantic comparison, typed defaults and receipt/schedule checks resolved it without a
  production change. The original failure and resolution remain in the report.
- Fake-provider chat streamed incrementally. Grouped settings worked at desktop/narrow sizes, including the actual
  narrow selector, exact About/version, scrolling, overflow and focus checks.
- Tool-created artifact drafts survived Settings/another-conversation navigation; explicit Save persisted exact
  content as revision 2. Settled search returned the synthetic conversation; Escape restored the opening trigger.
  Transition-time automated clicks were corrected after hit-test/readiness checks; no settled-search defect reproduced.
- Bounded headless FileServer Range checks returned exact 200/206 bytes and bounded 416 errors. This did not exercise
  the separate knowledge ServeContent handler or demonstrate resistance to every malicious workload.
- Representative screenshots were inspected. Collected browser sessions recorded no console/page errors or failed
  requests. Identity, providers, credentials and data were synthetic; native Wails/permissions were not exercised.

Reports: `pai-local-v042-qa/.cache/v042-prerelease-smoke/REPORT.md` and
`pai-local-v042-qa/.cache/v042-ui-smoke/REPORT.md`, including their completion appendices. Source/build hashes stayed unchanged.

restarted nor overwritten as part of release verification.
