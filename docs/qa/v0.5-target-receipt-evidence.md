## Scope and trust boundaries

- Reviewed descriptors retain both Darwin architectures on the byte-compatible Schema 1 path. Only explicit
  `NOTICE_TARGET=windows-amd64` / `linux-amd64` select Schema 2; a matching real Node process OS/architecture
  is required. Fake hosts are accepted only by the pure policy helper, never by the writer/reader.
- Windows contracts Go windows/amd64/CGO 0 and Node win32/x64. Linux contracts Go linux/amd64/CGO 1,
  default GTK4, and Node linux/x64. Go fields are target contracts, not observations of Go execution.
  Custom build tags and conflicting target environment are refused. Global Go environment is not mutated.
- The scanner functions were extracted verbatim; generator exports remain the identical function objects.
  Full recognized notice comparisons across peers, frozen-store/source-lock equality and declared dependency
  checks remain. The new installed-identity digest covers sorted unique IDs, the scanner's representative
  package.json byte hash and existing complete notice fingerprint. It does not cover every module source
  file or all peer manifests, and is not a full source-integrity attestation.
- Schema 2 snapshots include both package manifests, frozen locks and installed identities. Node version is
  observed from the actual process. Package-manager version is explicitly a declaration, not an executed
  version inferred from package.json or an untrusted user agent. Native CI separately checks actual pnpm
  11.18.0 in each package cwd; receipt code never shell-spawns a Windows `.cmd` to query versions.
- Evidence writes are confined to known area/target paths under `.cache/licenses/inventory/`; invalid
  inputs/snapshots fail before replacement. Evidence-path symlinks are refused. Successful replacement is
  atomic. The strict reader compares the full object with current policy/install/artifact snapshots and
  canonical JSON bytes, rejecting unknown claims, duplicate keys, Schema 1 and distribution-complete claims.
  It never falls back to a legacy file. CLI failures are sanitized and successes contain only a summary.
- Input IDs are the bundler hook's reported graph, not an independently reconstructed graph. Canonical input
  encoding/digests and current artifact hashes establish local consistency, not authentication or a signed
  attestation. Rewriting both a reported graph and its digest is outside this receipt's trust guarantee.
  Opaque virtual labels keep the old normalization semantics; source files are not all hashed.
- Receipts cannot establish legal coverage, a production Go graph, Node archive provenance, native-library
  coverage or distribution completeness. `distributionComplete` must remain false.
