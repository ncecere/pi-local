# Desktop startup capabilities — bounded v0.5 increment

Base: `3edc2d0`; branch: `v05/desktop-startup-capabilities`.
Implemented with GPT-6.1-sol only, without delegation.

## Contract and scope

`available` continues to mean desktop presence. GET and successful PUT now expose
`capabilities.launchAtLogin: {available, reason}`, using host availability semantics
and lower-case JSON fields. Missing/unknown capability keys fail closed. Unsupported
GET never invokes the getter; unsupported PUT returns 501 / `not_supported` before
reading the request body or invoking the setter. Pure API tests inject failing
getters/setters and a body reader that fails if touched.

The existing macOS LaunchAgent implementation and fake-HOME/plutil test moved to
Darwin-only files. Other platforms return `host.UnavailableError` wrapping
`host.ErrUnsupported` immediately, without home/executable/filesystem/command
access. No Windows registry or Linux autostart implementation was added.

Account settings retain the supported Mac toggle, pending disablement, optimistic
rollback/error toast, and accessible labels. Unsupported/missing capabilities show
an explanation and an unchecked disabled switch, without menu-bar promises.
Explicit supported/unsupported/absent TypeScript fixtures test this behavior and
verify no disabled mutation or cache change. Existing grouped navigation and
responsive layout were not changed. The development fake supports
`FAKE_STARTUP_UNSUPPORTED=1`; `FAKE_BROWSER=1` still models absent desktop.
