# v0.5 secret authority: test-only fault model

## Unresolved counterexample — protocol NOT approved

**Concurrent directory exclusion is not persistent directory ownership.** The
model admits this unsafe sequential trace:

1. Reference A publishes durable PENDING for directory D, then gets an ambiguous
   readback result before any DB exists. No grant escapes; both leases release.
2. Reference B acquires its own reference lease and the now-free exclusion for
   the same observed directory (including an alias). B sees absent authority in
   its own namespace and no DB, initializes, and receives an ACTIVE grant.
3. A's PENDING material remains, but A subsequently refuses B's DB binding.

The permanent test
`TestAuthorityModelUnresolvedCounterexampleSequentialReferencesGrantSameDirectory`
**passes only by witnessing the unsafe B grant**, retained A, and A's subsequent
refusal. It is an unresolved limitation/counterexample, NOT a safe-protocol
acceptance test. The original safety-expectation probe failed with exit **1**;
its exact command and output are preserved below. Green model tests do not close
this finding or approve a multi-reference/native protocol.

Custom-reference issuance/authorization is expressly **not modeled**. Explicit
profile creation and persistent ownership claims, or an intentionally default-only
scope, require separate design review. No catalog, ownership mechanism, scope
restriction, production/factory change or silent design fix is introduced here.
The existing transition algorithm and other model assertions are retained.

## What the model checks

- Authority and DB each have separate visible/durable snapshots. Authority writes
  change visibility; successful fake flush copies authority to durable state.
  A modeled crash discards visible state and restores durable snapshots.
- References are exact ASCII `default` or `profile:<canonical lowercase UUID>`.
  This checks grammar only, not authorization to issue/create a custom profile.
  Directory identities and alias equivalence are supplied observations, not path
  normalization, Windows alias handling or a root-recreation detector.
- Reference ownership precedes independent directory exclusion. While a lease
  is held, same-reference opens at different directories and different-reference
  aliases collide/refuse. Independent references at different observed directories
  can proceed. Leases last through a grant's lifetime; errors release only leases
  actually acquired, directory first. Counts and a per-owner event trace check
  ordering. The sequential cross-reference counterexample above remains admitted:
  correct concurrent exclusion alone does not establish persistent ownership.
- Fresh initialization acknowledges PENDING before creating the modeled DB.
  Metadata/schema/binding and zero rows appear in one committed image. Existing
  PENDING reuses the same root and promotes only after authenticated expected
  schema/binding and zero rows in the reconciled image. Partial DBs, missing
  required WAL, unauthenticated WAL and orphan WAL/SHM/journal fail/preserve.
- ACTIVE validation requires a DB and matching binding; an observed recreated
  root refuses. Every ACTIVE reopen flushes and validates exact readback under
  both leases **without a write**, even if it was acknowledged on a prior open.
  Visible-but-unacknowledged ACTIVE cannot produce a grant until a fresh ack.
- Faults before/after observation, both authority writes, both flush/readbacks,
  DB creation/commit/reconciliation, and mismatched valid-looking readback return
  no grant. Tests reopen both directly and after a modeled crash. Failed
  pre-commit initialization preserves a partial DB and refuses automatic repair;
  ambiguous completed commit can reconcile. No implicit retry/delete/reset occurs.
- Missing authority with existing ciphertext, malformed/unknown/version-1
  authority, format-1 artifacts and legacy credentials refuse without replacement
  or deletion. Legacy coexistence is conservatively refused, not imported.
- Nil/closed grants cannot perform secret operations. Granted CRUD changes only
  the DB. Before/after CRUD commit ambiguity reconciles old/new modeled images
  without changing authority. Close is idempotent and joins in-flight CRUD.
- Controlled channels block synchronous operations while cancellation and
  competing opens run. Snapshots prove both leases remain held, no grant escapes,
  collisions do not steal ownership, and release follows synchronous completion.
  There are no sleeps, native locks or timing-based completion assumptions.

## Deliberate limitations

This is a bounded executable transition model, not exhaustive model checking or
an implementation ready for activation. Authentication, integrity and expected
schema are explicit fake observations; UUID/key are public fixed identities.
Exact readback means Go record equality, **not a binary format or crypto proof**.
The secret DB has one opaque value slot, not names, SQL, encryption or providers.

Successful modeled DB commit installs a complete durable image; a commit fault
can occur before or after that effect. A retained partial DB is represented
separately from a committed schema. WAL reconciliation selects a supplied
committed image; it does not execute SQLite, test every WAL/SHM/journal condition
or establish SQLite/VFS durability. Successful modeled authority flush establishes
durability by assumption. Failure after a flush can leave durable material even
though the caller gets no grant. Neither fake proves actual durability, hardware
behavior or physical power-loss recovery.

The before/after fault cases do not promise crash-atomic phase replacement.
Malformed/torn authority is separately injected and refused; it is not repaired.
A model crash occurs after an injected failure has joined and released leases,
not by killing a process or exercising abandoned native ownership. Channel-owned
state and channel serialization are not Windows mutexes, OS thread pinning,
SID/ACL security, registry semantics, DPAPI, path alias/recreation exclusion or
protection against hostile same-user/privileged mutation.

The explicit indistinguishability tests demonstrate limits, not defenses:

1. Externally losing authority **and all artifacts** is indistinguishable from
   first use; the same fresh observation can initialize again.
2. Replaying stale valid PENDING against a genuinely empty authenticated DB is
   indistinguishable from never-activated PENDING, even after historical CRUD.

No resistance to deletion, profile/hive rollback, stale authenticated snapshots,
dishonest hardware or universal power loss is claimed. Keeping authority and
secret material outside app backup/restore is a requirement, not tested wiring.
The Windows factory must still refuse before I/O; no native Windows execution or
acceptance is inferred from Darwin regression tests.

## Review gate

The sequential cross-reference gap is unresolved and blocks multi-reference/native
protocol acceptance. Passing this model (including its explicit unsafe-trace
witness) does not approve native activation or strengthen durability/antirollback
assumptions. **Parent must read ALL new files in full and obtain independent
review**; neither review is claimed here. No delegation or push is performed.
Any explicit profile creation/ownership protocol or default-only scope decision
requires separate design review; this artifact does not make that decision.
