# Ubuntu 24.04 GTK4 desktop: compile-only gate

Status: prepared, **native run pending**. Branch `v05/ubuntu-desktop-build`,
base `483f655`. No native Linux desktop build result is claimed by this note.
No application, server or desktop test executable is launched by this workflow.

## Pinned source and target

The selected SDK is Wails `v3.0.0-beta.22`. Its checked module source selects
`pkg/application/linux_cgo.go` for `linux && cgo && !gtk3 && !android && !server`;
its cgo directives require `gtk4 webkitgtk-6.0`. The SDK's assetserver also uses
`libsoup-3.0 gio-unix-2.0`, and `global_shortcut_linux_x11.go` requires `x11`.
The presence of that compiled SDK code does not enable a Pi Local global hotkey.

The isolated workflow therefore targets **Ubuntu 24.04 x86_64**, with native
Go **1.26.10**, Node **22.23.0**, package-cwd pnpm **11.18.0**, default GTK4,
`CGO_ENABLED=1`, and readonly Go modules. It rejects another distribution,
version or architecture and asserts Go host and target identities. It does not
try GTK3, headless/server tags, CGO-disabled stubs, cross-compilation or a
missing-symbol waiver as a successful desktop build.

Stock Ubuntu repositories supply `pkg-config`, `libgtk-4-dev`,
`libwebkitgtk-6.0-dev` and `libx11-dev`, without recommended packages. Their
transitive distro libraries are part of this CI build environment, not a bundled
product artifact. The workflow records installed package versions and all five
pkg-config module versions. WebKit's `6.0` package/API name is not an assertion
that its upstream library release version is 6.0.

Only the disposable GitHub Ubuntu runner installs these dependencies. No local
Mac package installation or personal service configuration is involved. No
explicit AppArmor, sysctl, userns, capabilities, ACL or sandbox-policy overrides
or weakening are allowed. Stock package maintenance is not a confinement test.

## Compile-only checks

The workflow requires:

1. Native target and distro build dependencies, with no alternative repositories
   or downloaded privileged installer scripts.
2. Pinned toolchains and all 11 receipt-path Node regressions on Ubuntu.
3. Frozen runtime/frontend installs from their own package directories, followed
   by actual bundles before Go embed compilation. Receipt validation stays on.
4. `go build ./cmd/pi-local` and `go test -c ./cmd/pi-local` to fresh owned runner
   temporary outputs. Neither binary is executed. No `go test` execution, Wails
   production constructor, window, desktop session, D-Bus/credential operation,
   service activation or relaunch is requested by the application.
5. Read-only ELF/build-info inspection using `file`, `go version -m` and
   `readelf -d`. Require GTK4 and WebKitGTK6 dynamic dependencies, rather than
   mistaking a CGO-disabled/headless binary for a linked desktop. Do not use
   `ldd` or launch a binary to inspect it.
6. An always-run check that Go module files and both pnpm locks are unchanged,
   even after failure. Remove only the exact owned temporary output directory.

Permissions are contents-read only; the job is branch-guarded, has a 30-minute
limit, uploads no binaries and runs no packaging or release command. A failure
must remain red with its original evidence; do not patch the SDK/module cache,
relax readonly modules, add an unreviewed dependency upgrade or switch toolkit
backends to force a pass.

## Remaining evidence and distribution limits

Local workflow lint and source review are separate from a native build result.
Successful Windows compilation does not establish this Linux gate either.
Actual Ubuntu headers, compiler, linker and SDK compatibility must be observed
in the required native job before recording success.

Even a passing compile job would not prove GTK/WebView execution, X11/Wayland
parity, native startup/openers/notifications, contextual Secret Service behavior,
private transport, packaged dependencies/notices, installation or desktop E2E.
The existing notice inventory is Darwin-only; distro library installation does
not establish Linux distribution license coverage or legal clearance.

Linux confinement remains unavailable. The historical bubblewrap loopback
`RTM_NEWADDR: Operation not permitted` gate is not changed, bypassed or explained
by installing GTK headers. This job does not run bubblewrap or infer sandbox
acceptance from its hosted runner's kernel or package configuration.

No normal application, real vault, provider, personal AppSupport directory,
protected running app or reference checkout is accessed by this compile-only
increment. Portable agent SQLite folders and all runtime/secret policies are
unchanged. Native UI, containment and supported-OS release acceptance remain
separate requirements; no release is prepared here.
