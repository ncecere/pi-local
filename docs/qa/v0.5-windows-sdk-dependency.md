## Receipt path correction after first native failure

Starting revision: `324468b` (reviewed toast dependency/CI, not merged). First
native Windows run **39728846761** failed in the frozen asset step, exit **1**.
Runtime bundle/receipt generation passed (`runtime.mjs`, 1239 inputs). Frontend
Vite built its output, but `closeBundle` failed in `build-receipt.mjs`:

```text
Bundler input outside release worktree: D:/a/pi-local/pi-local/frontend/node_modules/.pnpm/lucide-react@1.29.0_react@19.2.8/node_modules/lucide-react/dist/esm/icons/map-pin-minus-inside.mjs
```

**Go desktop build and test compilation were not reached.** The always-run
module/lockfile immutability step passed. The original log remains untouched at
`.cache/windows-desktop-first-native-failure.log` (local ignored evidence, not a
committed artifact), SHA-256:
`512d86c5a71450b481e6702707315f775a9c0ad119316c39d8c05d1945c25b74`.

The absolute-input branch previously kept Vite's forward slashes while the
canonical Windows root used backslashes. It also tested an unnormalized absolute
`root/../outside` against the raw prefix. The correction resolves **both**
absolute and relative real inputs before the exact `root + separator` boundary
check. It does not case-fold, strip drives, accept aliases/outside inputs, or
bypass receipt generation. Windows case mismatches deliberately fail closed,
including on case-sensitive NTFS worktrees. The guard is lexical normalization,
not a new filesystem realpath/symlink-identity policy.

Virtual NUL/`virtual:` graph labels remain labels (no path resolution or real-file
containment). Only the known root prefix is removed; Windows slash variants are
normalized consistently without removing unknown roots, drives or sibling
prefixes. POSIX backslashes remain real filename characters for real inputs and
artifact keys. Receipt filesystem paths always use host Node semantics; injected
`path.win32`/`path.posix` implementations are limited to the pure normalization
helper and never simulate Windows filesystem writes on macOS.

`packaging/licenses/build-receipt.test.mjs` adds **11** tests for Windows slash
forms (including the exact failed lucide input), parent escapes, sibling/root
boundaries, different drives, case mismatches, UNC roots/aliases, Unicode/spaces,
virtual labels, POSIX literal backslashes, and actual host-native temp-root
receipt/hash/immutability/empty-graph behavior. On Windows, the actual writer
also receives native forward/backslash/mixed absolute inputs. No new test skips
or dependencies. `make test-licenses` now runs **21** tests: these 11 plus the
unchanged 10 notice tests. The Windows SDK workflow requires the receipt tests
on native Node 22 **before** frozen asset builds; its path trigger includes the
new test file. This requirement has not yet been executed in native CI.
