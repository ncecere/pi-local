## Supplied assumptions, not native identity proofs

The private candidate constructor binds **one supplied backend** to an expected
SID/fixed application observation. A matching observation must be marked fake
`Authenticated`; empty, unknown or mismatched observations fail closed at the
constructor and on every open. These static strings/boolean are **FAKE harness
assumptions, not OS authentication**. The expected binding and shared backend must
be supplied by a trusted constructor/namespace; this increment implements no
SID-to-backend catalog and proves no native namespace ACL or authorization.

Desktop/headless-compatible labels with the same supplied SID/application use the
same injected model. Caller executable path, `-data`/data label, agent ID, binary
label/version and filesystem UUID never choose the backend or reference. Their
equivalence tests are conditional on that constructor/namespace assumption, not
proof that real installations resolve the same native namespace. A different
subject/application cannot reuse this candidate.

Custom (including grammar-valid `profile:<uuid>`) and unknown references refuse
before calling the model, even with an already-cancelled context. They are not
silently rewritten to `default`. World equality checks cover counters/events and
material. A separate closed-channel actor canary would panic on **any** model
call, including a read-only snapshot, during preflight rejection. An admitted but
pre-cancelled default also makes no actor call.

## Both location policies remain UNSELECTED

| Candidate | Modeled behavior and limit |
| --- | --- |
| First initialization chooses | First B is allowed; subsequent A refuses the retained binding. No second independent default store is available by changing directories. A retained authenticated PENDING can reserve A **before acknowledgement completes**. |
| Enforced known directory A | Injected alias A is accepted; B refuses after reference acquisition but before directory lease, artifact observation or generation. This input policy still applies when authority/artifacts are all lost. Trusted derivation of known A is assumed, not implemented. |

`model.open` delegates to private `openWithAdmission(..., nil)`. Nil retains the old
behavior. The optional predicate runs on resolved `r.dir` from the injected
`Aliases` map, **after reference acquisition and before directory acquisition or
authority/DB observation**. This is not pre-lease filesystem resolution. No new
mutable world fields, second reference lease under held directory, copied
persistence state machine or filesystem/root-existence proof is introduced.

Tests compare wrapper/nil-hook outcomes and complete worlds as a **delegation**
check, not an independent historical algorithm. Preservation evidence also comes
from the minimal diff and unchanged old suite, validation oracle and unsafe
witness in the repeated gates.

## Tested reservation, ownership and acknowledgement

- The 28-case matrix covers both policies, PENDING write before/after, flush
  before/after, readback before/after/mismatch, then another location directly and
  after modeled crash. It checks the exact expected visible/durable PENDING,
  writes/generations, no DB/grant and no acknowledgement event after failed ack.
- Any valid retained PENDING in these visible/durable fault snapshots constrains
  the location even without a completed acknowledgement. A different location
  refuses without extra generation/write or material change. Same-directory
  alias resume uses the **same UUID/key**, with no extra generation and only the
  ACTIVE promotion write. It cannot create independent authority for another dir.
- Invalid/partial/wrong-location retained authority refuses without replacement.
- Every ACTIVE reopen flushes and validates exact readback without rewriting,
  even after a prior successful grant. Before/after/mismatched ack failures give
  no new grant. Existing model schema/binding/reconciliation semantics and the
  successful/validated-event oracle are reused, not weakened.
- Global `default` reference ownership excludes A/B contenders at different
  locations **before artifact scanning**, and independent directory ownership
  lasts through grant lifetime. Independent directory exclusion is also exercised
  through an original-model custom contender; the candidate itself rejects that
  reference earlier. Ownership traces retain reference-before-directory and
  directory-before-reference release ordering.
- Both policies exercise cancellation at every existing synchronous open
  boundary. Cancellation cannot detach the call or release its owner leases
  before completion. Candidate grants retain the existing close-joins-CRUD
  behavior, including a completed-but-cancelled modeled write.

**Correction/limit, not a defense:** a failure before the PENDING write leaves no
authority/artifacts; a crash can also lose merely visible, unflushed PENDING.
When **authority AND all artifacts are lost**, first-chooses can initialize at B.
The tests explicitly demonstrate this indistinguishability limitation (and a new
generation), not freshness or antirollback. Known-directory still rejects B by
its independent supplied input policy; that does not establish freshness either.

## Retained unsafe witness, NOT safety acceptance

`TestAuthorityModelUnresolvedCounterexampleSequentialReferencesGrantSameDirectory`
is unchanged and still passes **by observing the unsafe original-model B custom
grant** after A default retained PENDING/no DB. The new candidate separately
rejects custom B with zero backend calls, preserving A.

The old model does not model genuine root-existence/freshness or legitimate custom
issuance. Its witness is a counterexample to its permissive admission rules,
**not an unconditional protocol flaw**. Correct real fresh-root admission might
block that simple trace. Narrowing candidate admission does not prove that rule,
custom authorization, general persistent ownership or native security.

## DEFERRED: remaining root and namespace research

The following remain **DEFERRED, not done**:

- Dedicated-root existence/freshness, existing-empty versus created-during-open,
  authenticated object identity, root loss/recreation, publication and recovery.
  Existing `Recreated` flags are supplied observations, not a root lifecycle FSM.
- Visible/durable root lifecycle and actual root-filesystem publication/identity
  proofs. Actor observation/generation events are **not physical Root existence**.
- Native authenticated SID acquisition, fixed application identity across entry
  points/versions, namespace derivation, ACLs and authorization proofs.
- Actual path equivalence/known-directory derivation, Windows registry/DPAPI,
  native lifetime leases, codec/crypto, SQLite/WAL and hardware durability.
- Legitimate custom-reference issuance, backup/restore wiring, migration, and
  deletion/rollback resistance. Authority plus all-artifact loss and stale valid
  snapshots retain the old indistinguishability limits.

Successful fake flush/commit and exact Go equality remain supplied assumptions,
not OS/crypto/power-loss proofs. The reviewed design is unchanged. **No native
implementation approval and no policy selection follow from green tests.**
