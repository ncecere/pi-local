# v0.5 desktop relaunch boundary

Branch: `v05/desktop-relaunch-boundary`, base: `6c5782e`.
Implemented with `gpt-6.1-sol`, without delegation.

## Scope and behavior

`main.go` now passes the updater/API hook slots and Wails Quit callback to a
build-selected adapter. Only `desktop_relaunch_darwin.go` imports the command,
Darwin session attributes, and `update.CurrentBundle` dependencies. The
non-Darwin adapter clears both hooks without executable, bundle, filesystem,
PID, or command probes; its tests use fake App/Updater/API structs, not `app.New`
or native Wails. No Windows/Linux relaunch implementation is added. Main's
portable `syscall.SIGTERM` use remains intact.

On macOS, the updater hook is retained, and restore restart is wired only when
`update.CurrentBundle()` finds an installed bundle. Development builds retain a
nil restore restart hook. The shell source is constant:

```sh
while kill -0 "$1" 2>/dev/null; do sleep 0.2; done; /usr/bin/open -n "$2"
```

`/bin/sh -c` receives a constant `$0`, decimal parent PID as `$1`, and the raw
bundle as `$2`. There is no interpolation, Go `%q` shell quoting, or `eval`.
Injected process/wiring tests check raw argument identity for spaces, Unicode,
single/double quotes, backslashes, `$()`, backticks, semicolons, and newlines,
through both update and restore hooks. They also check lazy command creation,
development wiring, and that Start failure reports the existing error without
Quit or Wait. Real command construction is inspected without Start; no relaunch
shell, open, kill probe, or Wails Quit runs in these tests.

`desktopShellURL` selects `desktop-mac` only for Darwin and explicit `desktop`
for all other/unknown platforms. The existing shell-init script already replaces
session storage with any nonempty URL marker. Its new tests execute that actual
script with a fake document/storage and verify that a generic URL replaces a
stale Mac marker and survives navigation. The script's executable behavior,
grouped navigation, chrome CSS, notification implementation, and startup API are
unchanged; no frontend OS checks or dependencies were added.

## Helper lifetime and limitations

The helper intentionally retains `Setsid: true` and is not tied to cancellation
or shutdown cleanup. After successful Start, one goroutine calls `Cmd.Wait` to
own/reap an early exit while the parent remains alive. Quit does not wait for a
helper that is waiting for the parent. A blocking fake Wait verifies that Quit
is not blocked. After parent exit, the OS inherits the helper; the parent cannot
guarantee that its Wait finishes or even runs before process exit.

This preserves the **legacy, potentially unbounded PID-existence wait**. It is
not retained-process-identity proof: PID reuse can postpone open indefinitely;
probe failure can permit open, and abnormal parent death does not prove graceful
agent shutdown. There is no new timeout, kill fallback, deduplication, helper
protocol, readiness handshake, PID cleanup, transactional updater, or security
isolation. A successful Start is not proof that open eventually succeeds. The
existing post-swap Start-failure limitation remains; this is not rollback work.

The helper inherits the existing environment as before, not a newly isolated
one. No extra environment, data-directory arguments, working directory,
diagnostic streams, or descriptors are added. Wait errors are not emitted with
argv/environment. Start failure retains the existing `relaunching` error log.
No privileges are broadened.
