# v0.5 update installation boundary

Branch: `v05/update-install-boundary`, base: `3edc2d0`.

`update.InstallationCapability()` reports the installer compiled into the build,
without probing the host. Only the existing Darwin app-bundle installer is
available. Elsewhere, `Status` reports `canInstall: false` and an unsupported
reason even with a forged bundle/relaunch hook; it never runs the write probe.
Both installation entrypoints refuse with `ErrUnsupported` and a typed
`UnavailableError` before status/settings callbacks, stage changes, backup,
HTTP, filesystem access, context inspection, or relaunch. Errors contain only
build information. Unsupported bundle lookups return empty strings, and
unpack/swap stubs refuse without inspecting inputs.

App wiring changes only to `update.CurrentBundle()`: executable/bundle discovery
runs on Darwin only. Construction stays side-effect free. Darwin headless
blocked-reason semantics, asset selection, signatures, archives, and transaction
strategy are unchanged. All 11 original test/helper functions were compared
against the base and preserved verbatim across portable and Darwin test files;
all four original Darwin installer functions are also unchanged.
