# v0.5 verification — foundations in progress

No Windows/Linux desktop release or feature parity is claimed. Implementation/review/QA uses
`openai-codex/gpt-6.1-sol`; reference repositories and the user's running app remain untouched.

## Data-directory ownership

- Author `9d1ad24`, integrated `4e476b2`: owned persistent `.lock` handle, nonblocking Unix flock / Windows
  LockFileEx, idempotent close, contention-only error mapping. Acquire before restore/database work and release
  after shutdown. Lock files are never unlinked during normal use.
- Independent review approved. Native macOS unit/race/vet checks passed; initial Windows/Linux cross-compilation
  was explicitly not execution evidence.
- Native CI [39680140007](https://github.com/ncecere/pi-local/actions/runs/39680140007), source `af0df57`, passed
  `go test -count=1 -race -v ./internal/datalock` and vet on macos-15, ubuntu-24.04 and windows-2025.
  Tests use disposable helper processes and temporary directories: exclusivity in both process directions,
  independent directories, crash release, stable file identity, error classification and repeated/concurrent close.
- Windows Server CI exercises the Windows locking API; it is not Windows 11/WebView2 UI evidence. No keyring,
  shell sandbox, notification, installer, update or human-control boundary is validated by these lanes.

## Runtime discovery and environment

Author `7e624c5`, integrated `3bbfec6`: OS-aware PATH handling, explicit/bundled/PATH precedence, stable Node >=22.19,
Windows `.exe` discovery without implicit current-directory/PATHEXT execution, and an injected filtered-environment
helper. macOS login behavior is preserved; Linux uses its configured shell/sh fallback and Windows runs no login
shell. Environment inheritance excludes provider credentials and Node loader options.

Independent security review approved and reran macOS unit/race/vet checks successfully. Windows semantics use pure
local helpers; native Windows execution is pending the separate supervisor portability changes. Linux cgo=0
cross-compilation is not Linux runtime evidence. No real login profiles or personal application data used.

## Managed process ownership and combined native contracts

Author `3e8013e`/`04df318`, integrated `851a759`/`d0844d5`: contained start, single reap, identity-safe Unix group
signalling, explicit Windows refusal before launch, and supervisor/MCP lifecycle wiring. Initial review reproduced
loss of final MCP output when `cmd.Wait` closed `StdoutPipe` early. Caller-owned pipes now preserve unread output;
post-exit I/O is bounded, callback time is accounted separately, cancellation closes readers and cleanup joins watchers.
Independent re-review approved, with zero losses in original fast-exit, burst/slow-callback, handshake and large-result
probes. Targeted packages passed unit/race/vet checks. Callbacks must return; escaped groups/unexpected app death
remain documented Unix limitations. Windows Job Objects are not implemented yet.

Combined native CI 39683337914 passed macOS/Linux but found a Windows-only test assertion: `Stat` on a closed Windows
pipe returns invalid-handle, not Unix's closed-file error. `1d09175` checks the documented closed `Fd` sentinel instead;
no cleanup implementation was weakened. CI [39683657082](https://github.com/ncecere/pi-local/actions/runs/39683657082)
then passed race-enabled datalock/process/runtimeenv contracts and vet on all three native runners. Windows validates
fail-closed startup and shared contracts, not execution inside Job Objects or desktop support.
