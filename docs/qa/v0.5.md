## Windows secret-authority proposal (design only)

The [reviewed proposal](../design/windows-secret-authority-candidate.md) retains format 1 and Windows pre-I/O
refusal. A separate future authority-first protocol uses a stable logical reference, reference and directory
exclusion, PENDING/ACTIVE phases, and durable acknowledgement before any usable store. Independent review found
a Medium reopen gap: visible ACTIVE did not prove an acknowledged flush. The revised design requires flush and
exact validated readback on every ACTIVE open without rewriting immutable authority; bounded review closed it.
Pending promotion additionally requires expected schema/binding and zero secret rows after WAL reconciliation.
Registry hive flushing is a research candidate, not crash-atomic replacement or a native adapter. No v2 codec,
lease, protocol implementation, migration or factory activation is included. A later test-only model found a
sequential-reference admission counterexample: after A retains PENDING without DB and releases its leases,
B can obtain a grant for the same location in that model. Independent review qualified the result: the model
has no root-existence/created-this-open observation and does not establish the proposal's genuinely-fresh-root
premise; custom-reference issuance/authorization is also unmodeled. Strict existing-empty-root refusal could
block the simple trace. Root-loss/recreation and authorized issuance need explicit modeling before claiming
an extended fresh-root counterexample. Concurrent leases alone do not establish persistent ownership, but
this is not an unconditional protocol flaw or deployed exploit. Freshness, recreation identity and reference
authorization must be reviewed together; durable location ownership or narrower scope is needed if those
rules cannot prevent competing retained claims. No multi-reference/native acceptance is claimed.

The model is integrated as research only (`b072804`). Independent review found a Low completion-oracle gap;
parent separated successful flush, validated readback and verified DB events from mere completion and added
five rejection mutations. Bounded review closed the Low without changing the unsafe-admission witness.
Merged model gate `proc_ebac` passed 100 model repetitions, 20 race repetitions, vet and existing-secrets
normal/race checks (exit 0). [Model assumptions and preserved failed probe](v0.5-secret-authority-model.md)
remain explicit; no native factory or authority adapter is enabled. The separately reviewed
[default-only scope comparison](../design/windows-default-authority-scope.md) is a research alternative,
not a selected location policy or implementation. Its review clarified that retained authenticated PENDING
can reserve a location even before acknowledgement completes; ambiguity never permits replacement.
The [test-only first subset](v0.5-default-scope-model.md), merge `cf724bc`, now checks default/custom
preflight, injected known-directory admission, retained-PENDING location reservation and every-open ACTIVE
acknowledgement. Both location policies remain unselected. Parent/independent model100x/race20x/vet and
existing-secrets suites passed, with three intended negative mutation child exits1 (wrapper0). Merged gate
`proc_8566` passed (exit0). Native identity, root existence/recreation/publication and the rest of the research
plan remain deferred; neither protocol implementation nor policy selection follows from these fakes.
